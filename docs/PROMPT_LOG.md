# PROMPT_LOG

AI에는 프로젝트 스켈레톤, 설정 파일, 반복 코드와 테스트 코드 작성을 요청했다.  
세부 정책과 예외 처리 기준은 직접 설계하고, 생성된 코드를 검토해 필요한 부분만 사용하거나 수정했다.

## 사용 도구

- Codex: 스켈레톤, 설정, 반복 코드, 테스트 스크립트 작성
- Spring Boot / Spring Data JPA: 백엔드 API 구현
- MySQL / Flyway: 데이터 저장과 스키마 관리
- Docker Compose: 애플리케이션과 MySQL 실행
- JUnit / PowerShell / curl: 단위 테스트와 실제 API 검증
- React / Vite / Lucide React: 프론트엔드 구현

---

## 1. 프로젝트 초기 스켈레톤과 실행 환경

### 프롬프트 입력

```text
Java 21, Spring Boot, Maven, MySQL, Flyway, Docker Compose 기반으로
파일 확장자 차단 프로젝트의 초기 스켈레톤 작성.

- Spring Web, Validation, JPA, MySQL, Flyway 의존성 구성
- common, extension, upload 패키지 구조 생성
- 공통 응답, 오류 코드, 비즈니스 예외, 전역 예외 처리 기본 클래스
- DB와 JPA 설정을 위한 application.yml 기본 형식
- Flyway 마이그레이션 파일 기본 형식
- Spring Boot와 MySQL을 실행하는 Dockerfile과 Docker Compose
- 애플리케이션 기동 확인용 API

세부 테이블 구조와 비즈니스 로직은 제외하고 실행 가능한 기본 구조까지만 작성.
```

### 프롬프트 의도

프로젝트 초기 설정과 반복적인 공통 코드를 빠르게 구성하고, 이후 설계한 기능을 추가할 기반을 마련하기 위함.

### AI 결과에서 사용한 부분

- Maven 의존성, 패키지 구조, 공통 응답·예외 처리 기본 코드
- `application.yml`, Dockerfile, Docker Compose 기본 구성

### 직접 설계하고 수정한 부분

- 세 테이블의 컬럼·관계·인덱스와 고정 확장자 초기 데이터 설계
- Flyway와 `ddl-auto=validate` 조합 적용
- MySQL 포트 충돌을 확인하고 Docker 호스트 포트를 `13306`으로 수정

## 2. 확장자 관리 도메인 스켈레톤

### 프롬프트 입력

```text
현재 프로젝트 구조와 DB 스키마를 기준으로
확장자 정책 관리 도메인의 기본 코드 작성.

- ExtensionPolicy Entity와 Repository 기본 코드
- 정책 변경 로그 Entity와 Repository 기본 코드
- 조회·추가·수정·삭제 메서드를 가진 Service 기본 구조
- REST Controller와 요청·응답 DTO 기본 구조
- 공통 예외 처리와 연결할 수 있는 형식
- JPA 단위 테스트 기본 형식

고정·커스텀 정책, 제한값, 중복 처리, 삭제 가능 여부는
Service에서 별도로 구현할 수 있도록 메서드를 분리.
```

### 프롬프트 의도

Entity, Repository, DTO 등 반복 코드의 도움을 받고 확장자 정책의 구체적인 업무 규칙은 직접 구현하기 위함.

### AI 결과에서 사용한 부분

- 확장자 정책과 변경 로그의 Entity, Repository, DTO 기본 코드
- Service와 Controller의 계층 구조

### 직접 설계하고 수정한 부분

- 고정 확장자 삭제 불가와 차단 상태 변경 규칙 적용
- 커스텀 확장자 200개, 확장자명 20자, 중복 등록 제한 적용
- 정책 변경 종류와 `policy_change_logs` 기록 기준 구체화

## 3. 파일 업로드와 저장 코드 스켈레톤

### 프롬프트 입력

```text
Spring Boot multipart 파일 업로드에 필요한 기본 코드 작성.

- 업로드 요청을 받는 Controller 기본 구조
- 파일 검증과 저장을 담당하는 Service 기본 구조
- 업로드 이력 Entity, Repository, 응답 DTO 기본 코드
- 파일 저장 경로를 환경변수로 관리하는 Configuration Properties
- 파일명에서 확장자를 추출하는 공통 유틸리티 기본 코드
- 서버 저장 파일명을 생성하는 메서드 기본 구조
- 업로드 성공과 실패 상태를 저장할 수 있는 구조

확장자 판별 기준, 저장 파일명 규칙, 파일명 제한,
차단 검증 순서는 별도로 구현할 수 있도록 메서드를 분리.
```

### 프롬프트 의도

multipart 처리와 파일 입출력의 반복 코드를 활용하고, 파일 검증과 저장 정책은 직접 결정하기 위함.

### AI 결과에서 사용한 부분

- Controller, Service, Repository와 파일 저장 설정 기본 코드
- 확장자 추출, 저장 파일명 생성, 업로드 상태 저장 메서드 구조

### 직접 설계하고 수정한 부분

- 원본 파일명과 UUID 저장명을 분리하고 저장 경로 검증 적용
- 마지막 점 기준 확장자 판별과 파일명 길이 기준 결정
- 서버에서 최신 차단 정책을 재확인하고 성공·실패 이력을 저장하도록 구현

## 4. 최소 기능 테스트와 오류 수정

### 프롬프트 입력

```text
구현된 확장자 관리와 파일 업로드 API를 반복 검증할 수 있는
PowerShell, curl, JUnit 테스트 코드 작성.

- 확장자 목록 조회와 차단 상태 변경
- 커스텀 확장자 추가와 삭제
- 정상 요청과 실패 요청을 구분할 수 있는 테스트 함수
- multipart 실제 파일 업로드 요청
- HTTP 상태, 오류 코드, 응답 데이터 출력
- 테스트 파일 자동 생성
- DB 결과와 실제 저장 파일을 함께 확인할 수 있는 출력 형식

예상값을 변경해 재사용할 수 있도록 테스트 케이스를 분리.
```

### 프롬프트 의도

반복 테스트는 자동화하고, 실제 결과를 검토해 잘못된 로직과 예외 처리를 직접 찾아 수정하기 위함.

### AI 결과에서 사용한 부분

- API 요청과 테스트 파일 생성을 반복하는 PowerShell/curl 코드
- 확장자 추출과 업로드 Service의 JUnit 테스트 기본 코드

### 직접 설계하고 수정한 부분

- `.env`를 `env` 확장자로 처리하고 이중 확장자는 마지막 점 기준으로 수정
- 실패 예외와 함께 `REJECTED` 이력이 롤백되는 트랜잭션 문제 수정
- API 응답뿐 아니라 DB 이력과 실제 파일까지 검증 범위 확장

## 5. 동시성 처리와 파일 크기 제한

### 프롬프트 입력

```text
확장자 중복 등록의 동시성 검증과 multipart 파일 크기 검증에 필요한
설정 및 테스트 코드 작성.

- DB 데이터 무결성 예외를 공통 오류로 변환하는 기본 코드
- 동일한 API 요청을 병렬 실행하는 PowerShell 테스트 코드
- 병렬 요청별 HTTP 상태와 오류 코드 출력
- 단일 파일과 전체 요청 크기를 설정하는 multipart 설정
- 원하는 크기의 테스트 파일 생성 코드
- 정상 크기와 초과 크기 업로드 테스트 코드
- MySQL과 업로드 경로의 Docker volume 설정

동시 요청 개수, DB 제약조건, 제한 크기, HTTP 상태는
별도로 결정할 수 있도록 설정값과 테스트 변수를 분리.
```

### 프롬프트 의도

동시 요청과 대용량 파일처럼 반복 재현이 어려운 조건의 테스트 코드를 얻고, 데이터 정합성과 오류 기준은 직접 결정하기 위함.

### AI 결과에서 사용한 부분

- 병렬 HTTP 요청과 테스트 파일 생성 PowerShell 코드
- multipart 설정, 데이터 무결성 예외 처리, Docker volume 기본 코드

### 직접 설계하고 수정한 부분

- DB `UNIQUE` 제약을 최종 중복 방어로 적용하고 위반 응답을 `409`로 수정
- 동일 확장자 10건 요청에서 성공 1건과 DB 저장 1건 확인
- 파일 10MB·요청 20MB 제한을 적용하고 초과 응답을 `413`으로 수정

## 6. 다운로드 API와 React 프론트엔드

### 프롬프트 입력

```text
현재 Spring Boot API를 연결할 다운로드 API와 React/Vite 프론트엔드
기본 코드를 작성.

백엔드:
- 저장된 파일 목록 조회 API 기본 구조
- 파일 ID를 이용한 다운로드 API 기본 구조
- 다운로드 리소스와 응답 헤더를 구성하는 DTO

프론트엔드:
- 확장자 정책 조회·추가·수정·삭제 화면 기본 구조
- 파일 선택·업로드와 업로드 파일 목록 기본 구조
- 파일 다운로드 버튼과 API 호출 모듈
- 성공, 실패, 로딩 상태를 표시할 수 있는 구조
- 데스크톱과 모바일 기본 레이아웃

세부 UX와 데이터 동기화 방식은 별도로 추가할 수 있도록
컴포넌트와 API 코드를 분리.
```

### 프롬프트 의도

백엔드 API 연결과 React 컴포넌트의 반복 코드를 활용하고, 실제 화면 구성과 상태 동기화 방식은 직접 설계하기 위함.

### AI 결과에서 사용한 부분

- 파일 목록·다운로드 API, React 컴포넌트, 공통 API 호출 코드
- Blob 다운로드와 성공·실패·로딩 상태의 기본 구현

### 직접 설계하고 수정한 부분

- 고정·커스텀 확장자, 업로드, 다운로드 영역의 화면 구성 결정
- API 처리 후 DB 데이터를 다시 조회하고 다른 세션 변경을 동기화하도록 수정
- 추가·삭제·허용·차단 업로드와 원본 파일 다운로드를 직접 검증
